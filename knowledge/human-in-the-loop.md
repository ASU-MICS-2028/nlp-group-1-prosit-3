# Human-in-the-loop means people check AI output they can actually judge before it is used

Lecture 7's "blind person" analogy: using AI to write code in a language you cannot read is like a blind person using AI to recolour a photo. On good days nothing goes wrong; when the output is bad, you cannot tell. A sighted person spots the extra person added to the photo. So the goal is **fluency, not avoiding AI**: know enough to recognise when it is right, and why it is wrong when it is not. The course standard is that you must understand and be able to explain any code you submit.

Other lectures add: approval steps catch "did what I said, not what I meant" errors (Lecture 6), a user must be able to steer an agent mid-task (Lecture 8), and Lecture 9's grant agent asks for gaps and waits for approval before submitting.

**Example:** you can tell an AI "keep the email short" only because you can read English.

**For Prosit 3:** doctors must review every transcript before it enters a patient record; the system should make that review fast, e.g. by highlighting uncertain words.
